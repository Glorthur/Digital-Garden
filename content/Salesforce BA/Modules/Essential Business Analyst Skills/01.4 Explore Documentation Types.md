# 01.4 Explore Documentation Types

## Summary (Max 5 bullets)
- Documentation is a core BA competency and part of the communication-collaboration-documentation trifecta.
- Documentation types depend on project context, audience, and lifecycle phase.
- Typical BA artifacts include RACI, interview/elicitation records, stakeholder analysis, user stories, use cases, requirements specs, and visual docs.
- BAs maintain documentation continuously throughout the lifecycle, not as a one-time deliverable.
- Good documentation supports alignment, traceability, and better decision-making.

## Key Terms
- `RACI`: Matrix of Responsible, Accountable, Consulted, Informed roles for activities.
- `Interview and elicitation records`: Captured stakeholder inputs and requirement evidence.
- `Stakeholder analysis`: Artifact listing key stakeholders and their influence/needs.
- `User story`: Requirement statement from user perspective, often paired with acceptance criteria.
- `FRS/SRS`: Functional and system requirement specifications for expected outcomes and system behavior.

## Frameworks / Methods
- Documentation selection criteria:
  - Stakeholder audience
  - Project phase and objective
  - Level of formality required
  - Traceability and governance needs
- Formal vs informal documentation:
  - Formal: governed, reviewable, auditable artifacts
  - Informal: fast collaboration artifacts (notes/chats/drafts) used to accelerate alignment

## Salesforce-Specific Example
- For a Salesforce feature request, the BA creates: RACI for responsibilities, interview notes, stakeholder map, user stories with acceptance criteria, and visual flow/wireframe artifacts that support build and testing.
